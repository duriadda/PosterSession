# 포스터 내용 정리 (A0 절반, 영어, 단위는 상대값)

※ 수치는 모두 seed 1~40 평균

## 1. 제목·저자
- 한 줄 제목, 소속
- 시각 자료: 없음

## 2. 배경·문제
- 같은 추론 요청이 반복되므로 결과를 엣지 서버에 캐싱
- 서버 용량이 제한되어 있어서 어떤 결과를 어느 서버에 둘지가 문제
- Weather(추론 지연 1)와 Translation(추론 지연 18)은 캐싱 가치가 다름
- 시각 자료: 시스템 그림 (노드 → 엣지 서버 3대 → 클라우드)

## 3. 딜레이 모델·목적함수
- 요청 딜레이 = min(보유 서버로 직행, 가까운 서버 → 클라우드 → 추론)
- 목적함수 J = Σ_r Σ_i p[r][i] · delay(r, i)  (낮을수록 좋음)
- 한계이득 G(i, s) = 객체 i를 서버 s에 추가로 담았을 때 J가 줄어드는 양
- 예시: 가까운 서버 2, 먼 서버 7, 클라우드 2일 때
  - Weather: 먼 서버(7)보다 클라우드(2+2+1=5)가 빠름
  - Translation: 먼 서버(7)가 클라우드(2+2+18=22)보다 훨씬 빠름
- 시각 자료: 수식 2줄 + 위 예시

## 4. 제안 기법
- Baseline: 전역 인기 순으로 서버에 라운드로빈 배치 (거리·추론 비용은 보지 않음)
- Full MG: 매 단계 G가 최대인 (객체, 서버) 쌍을 확정, O(K·N·S·R)
- DW (Demand-Weighted): 서버별 수요 L로 가중 라운드로빈, 차례인 서버에서만 G 최대 객체 배치, O(K·N·R)
  - DW-distance: 거리 역수 비율로 수요 분배
  - DW-nearest: 가장 가까운 서버에 수요 전부 배정
- 시각 자료: 알고리즘 3개를 나란히 놓은 박스 또는 흐름도

## 5. 실험 설정
- 서버 3, seed 1~40 평균
- 선호 유사도 ρ = 0.5, Zipf α ~ U(0.6, 1.2) (노드별)
- 추론 지연 Weather 1 / Translation 18, 서버 → 클라우드 2
- 노드 → 서버 거리 1~8 (기본), 밀집도 시나리오는 home 1~3 / 그 외 6~8
- 용량 총 15 (5/5/5)
- 객체 수 N = 50, 100 / 노드 수 R = 3, 10, 30, 50, 100
- 시각 자료: 파라미터 표를 6~8줄로 줄인 것

## 6. 결과 ① 성능 → poster_figs/fig1_improvement_vs_R
- baseline 대비 개선율, N=50: Full MG 19.9~23.0%, DW-d 19.0~21.3%
- 60개 조건 모두 Full MG가 최선
- DW-nearest는 R=3에서 서버가 통째로 비어 크게 하락 (15칸 중 평균 10.8칸만 채움)
- 시각 자료: 꺾은선, x = R, y = 개선율, 알고리즘별 선

## 7. 결과 ② 성능 vs 연산량 → poster_figs/fig2_tradeoff
- Full MG 연산량 = DW-d의 2.06~2.38배 (60개 조건)
- 성능 차이(Full MG 대비 손실)는 약 0.6~2.5%
- 시각 자료: 산점도, x = 연산량(로그 축), y = 개선율

## 8. 결과 ③ 현실 시나리오 → poster_figs/fig3_density
- 조건: N=50, R=30, 밀집도 20:30:50
- Full MG의 J: 기본 6.407 / 밀집도 6.412 / 밀집도 + 용량 맞춤(3/5/7) 6.345 / 반대 배정(7/5/3) 6.512
- 밀집도 + 용량 맞춤이 J가 가장 낮음
- 이 시나리오에서 Full MG와 DW의 차이가 가장 큼 (DW-d 기준 1.2 → 1.8%p)
- 시각 자료: 시나리오 4개의 J 비교

## 9. 결과 ④ 최적해(MILP) 대비 (run_optimal.py, 그림은 아직 없음)
- 최적 대비 gap: Full MG 0.16~0.86% (seed 별로는 최대 4.0%)
- DW-d 0.72~3.08% / DW-n 0.75~20.1% (R=3 빈 서버) / baseline 16~31%
- MILP 풀이 시간은 Full MG의 약 12~22배
- 400회 모두 최적해 증명 완료

## 10. 결론·향후 연구
- 결론 (3줄)
  - Full MG는 baseline 대비 약 20% 개선, 최적해와 1% 이내
  - DW-distance는 연산량을 절반 이하로 줄이면서 성능 손실 1~2%
  - 노드 밀집도에 맞춰 용량을 배분하면 딜레이가 더 줄어듦
- 향후 연구: 서버 수 확장(5·10), 동적 요청 환경
